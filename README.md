# Electron + MFS Link Web SDK

A minimal Electron app that embeds the [MFS Link Web SDK](https://github.com/FrontFin/web-sdk/tree/main/packages/link-web-sdk)
(`@meshpayhq/link-web-sdk`) inside an iframe.

## ⚙️ Setup

Install dependencies (this also pulls the published `@meshpayhq/link-web-sdk`
npm package, pinned at `0.0.12`):

```bash
npm install
```

Copy `.env.example` to `.env` and fill in your MFS OAuth client credentials:

```bash
cp .env.example .env
```

| Variable | Environment | Description |
|----------|-------------|-------------|
| `MFS_CLIENT_ID` | Production | Production OAuth client id. |
| `MFS_CLIENT_SECRET` | Production | Production OAuth client secret. |
| `MFS_SANDBOX_CLIENT_ID` | Sandbox | Sandbox OAuth client id. |
| `MFS_SANDBOX_CLIENT_SECRET` | Sandbox | Sandbox OAuth client secret. |

Each environment has its own client id/secret pair — unlike legacy Mesh, there
is no id shared across both. The environment switcher in the app decides which
set is used per session request.

> **⚠️ Keep the client secret on your server.** This harness mints the OAuth
> token and creates the session in Electron's main process so it runs with no
> backend. That's only safe on your own machine. Anything inside a packaged
> desktop app can be extracted by its users, so in a real app call
> `POST /oauth2/token` and `POST /v2/sessions` from your backend and pass only
> the session's exchange code to the app. Start with Sandbox credentials.

Run the app:

```bash
npm start          # bundles the renderer with esbuild, then launches Electron
```

`npm start` (and `npm run dev`) rebuild the renderer on each launch — there is no watch task.

## 🚀 Use it

- **Production / Sandbox switcher** — a segmented toggle (Sandbox is the
  default) that picks which MFS credentials/API host are used to create the
  session, and which Link deployment `openLink` loads. These must match.
- **Destinations** — an editable list of token / network / wallet address rows
  that becomes the `transferOptions.toAddresses` payload. Networks are CAIP-2
  chain ids (`eip155:8453`, `solana:...`, `bip122:...`), per MFS's v2 API.
- **New Session** — mints an S2S OAuth token, calls `POST /v2/sessions` for a
  fresh exchange code (using the destinations and selected environment above),
  and opens Meshpay Link inside the embedded iframe via `openLink`.

## 📁 Project layout

```
main.js          Electron main process (window, header stripping, OAuth token mint + session create)
preload.js       contextBridge exposing window.mfs.createSession({ toAddresses, environment })
index.html       UI: environment switcher, New Session button, Destinations editor, #mesh-container iframe; page CSP
src/renderer.js  MFS SDK wiring (openLink) + Destinations editor state
dist/renderer.js bundled output (generated by `npm run build`, gitignored)
.env             MFS credentials (gitignored; see .env.example)
```
